# Devotion 部署與資安維護規則

更新日期：2026-11-13。適用每次文案、版面、功能、資產、套件、API、環境設定與發布。依三策通用發布規則轉譯，保留 Devotion 的私人資料、登入及草稿設計；來源見 `docs/source-inheritance.md`。

## 正式來源及授權界線

- 先從目前維護來源確認遠端、最新 `main`、工作分支、提交與正式網域，再修改候選版。2026-11-13 查核基準為 `devotion-book-webapp` 遠端 `main` 提交 `8f8efb74846d74633a0a5711253dac884e152e86`；這是本輪起點，後續工作仍重新查核最新狀態。
- 正式網域以平台實際設定及既有 `www.devotionbook.com.tw`／`devotionbook.com.tw` 設定核對。文件、README、版本文字與平台資料有差異時記錄差異，不能只採最早的文字。
- Devotion 既有 GitHub 儲存庫為公開來源。不得把三策私人儲存庫規定變成未經授權的可見性變更；應查核目前公開內容、權限及可用的分支保護。`package.json` 的 `private` 欄位與 GitHub 可見性分別認定。
- 本輪先完成本機候選版、檢查及修改前後對照；使用者檢視新具體預覽並明確批准後才發布。既有授權涵蓋可逆的本機工作，不為每個步驟新增確認。
- 版面與部署授權不包含正式資料寫入、資料庫遷移、RLS／角色、Auth 供應商、金鑰輪替、平台權限、監測、備份、快照保留期與付費設定的變更。這些變更另按使用者對該項目的指示執行。

## 修改前的查核與回復準備

1. 每次讀取根目錄 `AGENTS.md`、本規則、設計與文案規則、API 清單、既有資料隔離 SOP 與本次相關測試。列出影響頁面、共用樣式、API、資料表、Storage、Auth、套件及雲端設定。
2. 保存原有差異與可用基線，不覆蓋使用者修改。從最新 `main` 建立工作分支，記錄基底提交與本輪範圍。
3. 保存上一個已驗證正式部署的版本、提交、部署識別及設定差異。資料格式或遷移另列向前／向後相容性及回復步驟；回復不得重新公開已封堵入口或外洩金鑰。
4. 涉及資料或金鑰時核對既有備份涵蓋及還原證據。新備份、還原、快照刪除與排程各自依明確授權；發布不觸發備份、保留期清理或常駐監測。
5. 讀取既有 Vercel、GitHub、Supabase 設定時只記錄所需狀態與遮蔽資訊。不得輸出 `.env` 全文、服務金鑰、cookie、登入權杖、密碼、私人附件、完整 IP 或帶權限網址。

## 本機與預覽資料隔離

- 本機優先使用隔離瀏覽器 context、合成札記／禱告／書籍與可重建的本機種子。啟動埠須確認 PID、指令及工作目錄；既有 4173 埠有服務時先辨認所屬專案，不直接視為本次候選版。
- Preview 網址或警示橫幅不構成資料隔離。現有 SOP 已記錄 Preview 曾連到正式後端；每次讀取候選設定與實際網路請求，驗證不會把合成資料送往正式 Supabase、Storage、寄信或管理 API。
- 隔離設定缺少時明確失敗或停用寫入，不回退正式服務。不把正式服務端金鑰放進 Preview、CI、瀏覽器或本機測試種子。
- Supabase 公開用戶端識別設定與具高權限的服務金鑰分開辨認；公開用戶端設定的存在不等於服務金鑰外洩。私人資料仍須 RLS／物件擁有權與適當登入驗證，不依公開設定保密維護授權。
- 已授權的獨立 staging 應使用其專屬環境、帳戶、資料與憑證，不複製正式使用者、內容、頭像與檔案。本輪未授權建立新雲端專案或修改 Auth。
- 本機 mock 可證明介面與本機流程，無法證明正式 Supabase 寫入、跨裝置同步或郵件成功。驗收報告分開列出這些限制。
- 正式站自動驗收預設不登入、不新增／編輯／刪除資料、不寄測試信、不上傳或匯出私人內容。必要的正式登入觀察沿用使用者手動登入，不索取密碼。

## 公開產物與內部文件

採清單式 `dist` 打包，僅包含已列明的公開頁面、樣式、程式、manifest、版本、favicon 與公開 `assets`。API 由 Vercel 的 serverless 包裝獨立部署並維持原有服務端授權，不將函式來源複製成公開檔案。

公開產物必須排除：`AGENTS.md`、內部 `docs`、本機工作與測試資料、`tests`、`scripts`、資料庫 schema／SQL、讀取器歷史快照、備份、原始私人附件、金鑰及憑證、`.env`、`.git`、鎖定以外的安裝資料、來源對照檔，以及三策私人規則原文。內部規則可保留在版本控制，但不得因根目錄靜態發布而直接開放下載。

允許清單要與實際必要檔案一致，檢查路徑跳脫、大小寫、符號連結、巢狀檔案及新資產；不能只確認資料夾名稱。建置須從可預期的乾淨輸出產生，不沿用前次殘留檔。未知檔案或必要檔案缺少均使檢查失敗。

私人札記、禱告、使用者書籍、搜尋內容及帳戶資料不得預渲染、打包到 `dist`、寫進公開範例、OG／結構化資料、分析事件或錯誤紀錄。`noindex` 不取代伺服器授權及資料隔離。

## API 清單、授權與資料

維護機器可讀的 API 清單，逐項記錄實際路徑、方法、用途、登入條件、資料範圍、是否寫入／寄信、快取及必要測試。新增函式、別名、路由或回傳欄位前同步更新。來源掃描與建置掃描均核對清單，未知 API 不可默默上線。

目前候選包含下列兩項。發布前再次核對方法與回傳行為。

| 來源／路徑 | 基本驗收界線 |
| --- | --- |
| `api/admin-usage.js`／`/api/admin-usage` | 管理資料由服務端驗證授權；未登入 GET 應拒絕且不回傳管理資料 |
| `api/system-backup.js`／`/api/system-backup` | 備份查詢與下載由服務端驗證；不以本機管理畫面隱藏作為保護；不在正式站觸發新備份測試 |

- 假定對方已讀過舊原始碼、路徑、參數、欄位及檔名。API 與 Supabase 端驗證登入、擁有權與可讀欄位；前端隱藏、瀏覽器旗標、路徑難猜及 WAF 均不構成資料授權。
- 使用合成資料驗證未登入、偽造、過期、撤銷與跨使用者存取；管理權限與一般登入分開驗證。未登入及無權限請求不回傳私人內容，受保護回應禁止公開快取。
- 查核 `devotion_notes`、`devotion_prayers`、`book_projects`、`book_snapshots`、`library_books`、`library_book_chapters` 及 `library-books` Storage 的實際範圍，不用前端使用者 ID 直接當成授權。
- 切換身分、登出、恢復草稿及讀取 IndexedDB／localStorage 時，前一使用者內容不得顯示給另一身分。保留草稿與復原，不套三策土地評估的離開清空。
- 匯入 EPUB／HTML 與附件需依現有安全解析、檔案大小及格式限制；書稿文字、檔名與章節內容視為不可信輸入，不能繞過既有轉義及安全呈現。
- 保留已移除功能的拒絕行為；路由別名、尾斜線、舊環境變數與切換參數均須查核。更新不可藉新路徑恢復已停用功能。

## 每次候選版的必要檢查

| 檢查 | 通過條件與證據 |
| --- | --- |
| 來源與差異 | 最新基底、工作分支、預期檔案與 `git diff --check` 通過；未混入使用者未授權變更 |
| 重現安裝 | `npm ci` 使用 lockfile；新增或更新套件依官方修補資訊查核；`npm audit --audit-level=high` 無未解決高／嚴重弱點 |
| 語法與既有驗證 | 執行目前實際存在的 `npm run check`、`validate:scripture`、`validate:mcheyne`、相關聖經 EPUB 驗證及 `npm run verify`；記錄命令、候選提交與結果 |
| 介面與資料流程 | 依變動檢查起筆、保存、復原、列表／搜尋、禱告、選文、排序、快照、匯出、書房與閱讀器；合成資料成功／失敗狀態都驗證 |
| 文案 | 本機 `verify:copy` 與人工逐句覆讀；保護使用者原稿與引文；改字後檢查所有入口 |
| 來源資安 | 本機 `verify:security` 核對 API 清單、路由、服務端邊界、公開設定與私人檔案排除；安全測試採本機合成資料 |
| 建置產物 | `npm run build` 產生清單式 `dist`，完成後強制掃描實際產物、路由、文案與必要資產；內部文件及敏感內容均排除 |
| 金鑰掃描 | 全 Git 歷史 Gitleaks 與服務商辨識案例通過；輸出遮蔽。禁止只掃最新差異、關閉偵測器或寬鬆忽略整個目錄 |
| 工作流程 | 發布 PR 具完整網站驗證與獨立 `secret-scan` 必要檢查；外部 Actions 固定完整 SHA；不以 `continue-on-error`、刪測試或停用檢查通過 |
| 視覺與可及性 | 修改前後同條件對照、多尺寸、對比、鍵盤、焦點、可見性、Safari 與必要實機，依設計規則記錄 |

本輪已實作 `verify:copy`、`verify:security`、API 清單與 `dist` 產物檢查，候選版的實際結果依驗收紀錄認定。腳本存在與通過狀態以實際程式、輸出及測試為證。現有儲存庫沒有的 CI 工作、平台分支保護與掃描不能由文件宣告成已啟用。

測試按變動選擇並完成既有必要檢查；失敗項目先修復及複驗。選取器優先穩定標記，其次語意角色、名稱與可見區域。不得以強制點擊、程式代按、任意等待或修改使用者文字使測試通過；`networkidle` 也不作單一完成標準。現有失敗若與本次無關，仍需列明原因及發布阻擋狀態，避免假報全數通過。

## 正式發布前

1. 提供可操作的具體預覽、修改前後對照、檢查結果與未驗項目，完成使用者對該版本的明確認可。文案公開改寫保留前後文字；主要版面變更先看完整畫面。
2. 從最新 `main` 的工作分支建立 PR，確認實際待合併提交與必要檢查相同。禁止直接推送 `main`、強推、刪主分支或繞過必要檢查。
3. 讀取 GitHub 儲存庫可見性、分支規則與 Actions 結果，核對管理員是否受規則涵蓋。可用功能與權限不足時如實列出；未授權更改平台規則或購買方案。
4. 版本依變動性質更新，核對 `package.json`／lockfile、`APP_VERSION`／日期、`version.json`、資產查詢參數及 CHANGELOG。原內容的發布日期不跟著改成部署日。
5. 讀取 Vercel 實際建置命令、公開輸出、正式與 Preview 環境範圍、預覽保護、網域與 HTTPS；建置須執行必要檢查且公開輸出指向 `dist`。讀取既有安全標頭與 CSP，不以檔案存在宣告已生效。
6. CSP、外部資產、frame、MIME 與 referrer 等限制按現有服務需要驗證，避免過寬或阻斷登入、EPUB、字型與下載。變更設定保留前後差異；不關閉平台防護繞過驗證。

## 部署後與失敗回復

1. 讀取實際 Vercel 正式部署：精確提交、部署識別、`READY`、`production`、正式網域及時間。PR 合併與建置成功各自記錄，繼續驗證正式站。
2. 以最低影響 GET 查核首頁、版本、必要資產、變動入口、HTTPS 與實際安全標頭；`/api/admin-usage`、`/api/system-backup` 的未登入 GET 驗證拒絕結果，不下載資料。收款證明端點已移除，發布後以讀取請求確認舊路徑已停用。
3. 確認正式頁未出現合成種子、預覽標示、私人內部檔案；舊資產快取與版本提示正確。檢查主控台、載入錯誤、應用錯誤及網路狀態。
4. 完成受影響操作的最低影響驗收；只有本機可驗的資料流程保留本機證據，不在正式資料庫重做寫入測試。查閱既有錯誤紀錄時區分維護驗證與一般流量，不輸出私人紀錄。
5. 發現未授權資料回應、服務故障、金鑰外洩或防護退回時停止完成宣告，封閉受影響入口或回復仍符合安全條件的部署並複驗。涉及憑證輪替及資料回復時依其授權範圍辦理；回復部署無法撤回已被取得的憑證。
6. 完成紀錄列出提交、版本、部署、實際檢查及結果、API 拒絕測試、平台設定、受影響流程、未驗項目與原因。避免宣稱全面安全或將已知阻擋項目留到下次發布。

## 資料庫、Auth 與備份的獨立變更

純版面任務保留資料庫與 Auth 設定。若使用者另行授權，先在隔離環境檢查 schema、RLS、policy、函式、角色、Storage、預設權限與回復路徑；測試未登入、一般使用者、管理權限及跨使用者存取。正式遷移前後核對表／筆數、資料完整性、權限與既有連線，避免把缺少查詢權限寫成資料不存在。

Devotion 的正常註冊、信箱驗證與既有 Google 登入依產品實際需要保留。三策關閉註冊、專用服務角色及報告封裝的商業規則不直接套入。新增供應商、改付費 Auth 方案、刪使用者、合併身分與變更金鑰不隨設計任務執行。

備份表、書籍快照、可攜 EPUB、瀏覽器復原與完整災難還原是不同範圍。既有部分表備份、未涵蓋的禱告／快照及僅有 metadata 的匯入檔案須如實記錄；不以「完整備份」概括。改版不改定時器、保留數量、排程或還原方式；依既有災難重建 SOP 查核當次可恢復範圍。
