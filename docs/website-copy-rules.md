# Devotion 網站文案與回覆規則

更新日期：2026-11-13。依使用者指定的三策寫作規則與本輪靈修網站要求訂定。用語要求適用助理所有回覆，以及本站全部系統文字、平台撰寫內容與宣傳；使用者原稿及引文的保護方式另見下節。

## 適用文字與原稿界線

盤查範圍包含主標、小標、導言、摘要、正文、按鈕、輸入提示、空狀態、載入／成功／錯誤訊息、工具提示、說明、帳戶流程、圖說、替代文字、頁面標題、搜尋／分享摘要、SEO、結構化資料，以及由系統產生的通知與信件。共用字串、條件分支、Unicode 跳脫與執行後產生的文字均須檢查。

使用者的札記、禱告、書稿、匯入書籍、聖經原文、明示的直接引文與原始紀錄保持原意及字句。用語掃描不得靜默修改或禁止保存這些內容。平台自行撰寫的範文、示例、預設提示與空狀態仍遵守本規則。引用需標明來源及範圍，例外限於該段引文，不延伸到周圍系統敘述。

禁令適用一般對話、分析、進度、確認、草稿與最終交付。每次送出前逐句覆讀，直接寫具體事實、判斷、條件、責任與行動。以下為內部禁令宣告，保留原詞供維護與掃描；不得將這些清單搬到可見網站或完成報告。

## 禁用詞、句型與語意檢查清單

### 固定禁詞與空泛前導

- 固定禁詞：`真正`、`從來`、`口徑`、`對帳`、`補款`、`值得追問`、`同樣要回答`。
- 禁用前導與 AI 套語：`值得注意的是`、`更重要的是`、`這也提醒我們`、`讓我們先思考`、`值得警醒`、`有一個更前面的問題`、`背後還有一個問題`、`我們很容易問`、`一個很深的`、`整理情緒`、`需要一直記得`，及以 `長出來` 作抽象結果的套語。
- 不用 `有時候` 開頭；不以 `往往`、`其實`、`很多時候` 代替事實依據。相關命中須逐句覆讀，避免以另一個泛稱保留空句。
- 刪除為文章或設計自評的句子，例如 `有分析價值的批評`、`較精準的評價`、`值得承認的進度`；改述已發生的事實、未完成項目與判斷依據。

### 禁用句型

- 禁用 `不是……而是……`、`不在……而在……`、`不能只……還要……` 等對照套句。
- 禁用先假設讀者誤判再反向否定的句型，包括 `不能據此認定`、`不能僅因……便認為`、`無法據此認定`、`不足以認定`、`不能因此推論`。改成 `不代表`、`並不` 或刪掉否定詞後保留同一空泛提醒，仍須重寫。
- 直接寫已知事實、未公開或未驗證的具體項目、成立條件與結果。必要限制緊接相關主張。
- 平台撰寫的主標、小標、摘要與宣傳不使用設問、反問、自問自答、假想讀者對話與吊胃口問句。禁用此用途的中文／英文問號、`怎麼`、`為什麼`、句末 `嗎`、`呢`；真實使用者問題與原文引用保持原文。

### 泛稱動詞、抽象名詞與比喻

- 一般對外敘述不用 `處理`、`獲得處理`、`後續處理`、`處理工具`、`處理窗口` 代替具體行為。依實際功能寫保存、同步、載入、匯入、匯出、合併、移除、復原、寄送或答覆。正式名稱與技術既有名稱保留原文。
- `須`、`應`、`確認`、`評估`、`檢驗`、`比較`、`說明` 等詞後寫出對象、資料、方法、負責人或結果，不單獨作結論。
- 禁用 `帳算清楚`、`算清楚`、`算得清楚`，以及用 `帳` 比喻成本、利益、分配或責任的套語。清單中的財務原詞只供辨識，不套用到靈修敘述。
- 注意詞彙：`說清楚`、`講清楚`、`看清楚`、`釐清`、`攤開`、`落地`、`關鍵`、`核心`、`本質`、`配套`、`推進`、`銜接`、`檢驗`、`評估`、`安排`。出現時覆讀整句，補足行為、對象、依據與影響，或刪掉沒有資訊的句子。
- `帳戶`、`帳號` 等具有明確資料含義的詞逐項核准保留，不能為避開單字掃描而改成生硬名稱。未列明的含 `帳` 字詞先列入編輯覆讀，不直接認定違規。
- 不把三策的土地、融資、付款與責任用語移到札記；其可繼承部分是明確主詞、行為、資料與結果。禁止以抽象名詞堆疊或同義替換掩蓋資訊不足。

## 平台文案的具體寫法

1. 使用自然的臺灣繁體中文，先寫當前動作與可驗證結果。每段完成一個意思，避免口號、情緒代言、擬人化平台、誇大承諾及重複立場。
2. 按鈕寫出動詞與需要的對象；同一功能的名稱在列表、編輯、閱讀與匯出一致。標題、欄位及摘要區分用途，不用多個相近名稱指同一狀態。
3. 短記允許暫用日期，介面不以未填標題暗示內容不完整。保存成功須依實際結果顯示；載入失敗和空內容須區別。
4. 保留必要的刪除、覆蓋、登入過期、未保存、同步衝突與匯出失敗訊息。文字簡短仍須讓使用者知道受影響內容、後果及可採取動作。
5. 提示出現於使用者需要的位置，避免重複提醒或每頁常駐長篇說明。操作所需的限制在進行前說明，不等資料消失後才告知。
6. 說明文件面向一般使用者，描述可按的名稱、條件及結果。工程、管理後台、資料表、金鑰、測試種子等內容留在內部文件，不放進日常讀寫流程。

## 狀態與能力的證據

| 顯示的概念 | 文字成立條件 |
| --- | --- |
| 暫存 | 指明瀏覽器暫存或其他實際位置，依現有復原機制運作 |
| 已保存 | 對應該資料寫入成功；雲端與本機各自說明，不混用 |
| 已同步 | 遠端回應成功且資料可再讀；未驗證的跨裝置同步不得宣稱 |
| 已匯出 | 實際產生可開啟的檔案；雲端書房上傳及備份另行判定 |
| 草稿／已存內容 | 維持現有私人編輯狀態，沒有公開含義；若保留「發表」名稱須說明其私人範圍 |
| 禱告回應 | 由使用者選擇及記錄，不由日期、次數或平台推斷 |
| 書籤／閱讀進度 | 按目前實作分別說明本機及雲端範圍，不統稱所有書籍均跨裝置同步 |
| 離線 | 列明實際可讀、可寫、可保存及可恢復的範圍；部分本機資料不等於完整離線能力 |
| 備份與還原 | 說明涵蓋的資料、檔案與限制；歷史部分表備份不得命名為完整還原 |

「自動」僅用於已實作並驗證的技術行為，例如現有自動暫存，須寫明觸發條件與限制。禁用以該詞宣告權益、資格、責任、信仰成長、禱告結果或其他推論必然成立。平台不得以保存筆數或持續天數保證使用者的靈命、情緒與生活結果。

## 聖經、引文與信仰應用

- 保留聖經原文、版本、出處及必要上下文。個人反思、編輯說明與引用使用可辨識的結構，不讓心得看似經文。
- 先按原始語境理解，再提出適用條件與應用。聖經應許不改寫成個人必定獲得健康、財富、關係改善或其他結果的保證。
- 不用制式鼓勵取代具體內容，不替使用者判定感受、虔誠、順服或禱告是否有效。涉及具體危險或責任時，保留必要行動與求助資訊。
- 數字、歷史、作者與引文查核一手或可信來源；不虛構見證、案例、使用心得及研究成果。已知、估計、假設與未查核項目分開寫。
- 使用者原稿只依其編輯指示改字；網站版型修改不得順帶改寫其信仰立場、內容與經文。

## 排版、日期與公開資訊

平台長文靠左、自然換行；依思想分段，不套社群短行、不用裝飾序號與大面積粗體製造層次。使用者編輯器提供的格式能力與使用者原稿保持有效；三策文章的專屬排版不剝奪使用者的書稿格式。

發布日期與修改日期按實際紀錄顯示，不將全部日期更新成部署日。改題名時同步檢查首頁、近期內容、列表、搜尋、閱讀器、成冊、匯出與可公開的分享資料。

公開介紹及說明可依其內容建立 SEO；私人札記、禱告、書籍與附件不產生公開索引、公開 OG、公開結構化資料、靜態全文或搜尋引擎站點地圖。`noindex` 僅限制索引提示，私人資料仍須權限隔離。

## 每次修改的文案盤查

1. 修改前保存原文與預計改文；列出可見範圍，避免只改使用者圈選的一句。
2. 執行本機 `verify:copy`，掃描全部平台來源文字、共享與動態字串；建置後再次掃描實際公開產物。原稿與引文例外須有範圍、理由和位置，禁止整檔寬鬆忽略。
3. 逐句覆讀主詞、動詞、對象、條件、來源、結果、語氣及銜接。掃描通過只代表機械檢查通過；同義套語和語意缺漏仍須改寫。
4. 核對保存、同步、私人狀態、禱告、離線與匯出文字是否符合實作；失敗情境與成功情境都實際查看。
5. 保存命中位置、前後文字、引用保留理由、覆讀結果與未決項目。標題與共享字串修改後檢查所有入口及多尺寸斷行，再依發布規則完成驗收。
